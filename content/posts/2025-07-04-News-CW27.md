# amq broker 8 without openwire

Easy migration from AMQ 7 is a priority
AMQ 7.13 will have a longer support cycle to allow upgrading
Openwire Protocol will be removed.


The AMQ Operator and container images will be released independently of the AMQ broker
Red Hat build of ArkMQ(previously ArtemisCloud) will replace the AMQ Operator
Fast iteration of releases (first release pre AMQ 8)
Decoupled from AMQ broker version
Stable/Dev channels for releasing


New CRDs
Broker provisioning CR will deploy a broker service
Application CR’s will create application specific destinations, QoS, and authentications scheme.

Broker Service CRDs
Brokers provisioning CR will deploy a restricted broker
Fully locked down for everything including JMX and metrics
No Passwords/ mTLS everywhere
Certificates provided by Integration with the cert manager


Broker Service CRD
Operation rather than configuration 
Solutions rather than Capabilities
Opinionated, deterministic deployment, backed by:
Leader follower for HA
AMQP federation for moving messages on demand
AMQP mirroring for DR, replication
Static Routing - data gravity


Application CRD
Applications CR’s will deploy resources needed in the broker service
Acceptor 
Destinations
Roles and any certificates
Multi tenant view using RBAC
Certificates etc will be created for the clients to use



Application CRD’s
Application CR’s will allow an application to request a QOS which may be realised by:
Single broker
Federated Brokers
Mirrored Brokers
A mixture


An AMQP Bridge
Bridge to any AMQP endpoint
Aligns All AMQ to AMQP (Federation, Mirroring)
alternative to core bridge and jms-bridge using an open standard protocol that does SASL

Federation will replace Clustering as the default message distribution solution
Support on demand distribution
No more stampeding herd issues (moving all messages)
No complex topology state management
Supports AMQP inline with our other AMQP offerings
Bi directional
Brokers can be configured independently
Or not configured at all (unaware of federation)


Mirroring will replace replication as the default Message HA/DR solution
Better suited for cross data centre use cases
No complex catchup algorithms
Less problematic as only messages and acks are mirrored not the whole journal


OpenShift Integration will be GA
May reflect in some part new CRD’s
